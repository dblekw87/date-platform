# DATE Market Board Portfolio Case Study

## 한 줄 소개

DATE Market Board는 국내/미국 주식 시장을 함께 확인하는 사용자를 위해 시황, 뉴스, 일정, 공시, 수급 데이터를 한 화면에서 정리한 Next.js 기반 금융 시장 대시보드입니다.

## 제작 배경

주식 시장을 확인할 때 시황, 뉴스, 경제 일정, 공시, 수급 데이터를 각각 다른 서비스에서 확인해야 하는 불편함이 있었습니다. 이 프로젝트는 투자 판단 자체를 대신하는 서비스가 아니라, 판단 전에 확인해야 할 시장 정보를 한 흐름으로 정리하는 정보 보드를 목표로 제작했습니다.

특히 금융 대시보드는 랜딩 페이지처럼 보기 좋은 화면보다, 장중에 빠르게 읽히고 깨지지 않는 정보 구조가 중요하다고 판단했습니다. 그래서 화면을 시황, 뉴스, 일정, 속보/공시, 수급/차트 탭으로 나누고, 사용자가 실제로 확인하는 순서에 맞춰 정보 우선순위를 설계했습니다.

## 핵심 기능

### 1. 시황 보드

- 미국 지수, 국내 지수, ETF, 환율, 금리, 원자재, BTC 등 주요 시장 지표를 카드 형태로 표시
- 상승/하락 방향을 국내 투자자에게 익숙한 색상 체계로 구분
- 시장 흐름을 브리프 카드로 요약해 첫 화면에서 기준점을 빠르게 파악 가능

### 2. 뉴스 타임라인

- 국내 뉴스, 미국 뉴스, 테마 뉴스, 매크로 뉴스 필터 제공
- 헤드라인, 시간, 공급자, 분류, 원문 링크를 함께 표시
- 뉴스 원문과 정규화된 텍스트를 분리해 추후 번역/요약 확장 가능

### 3. 일정 캘린더

- 실적, 공모주, 신규상장, FOMC, 매크로 일정 등을 월간 캘린더로 구성
- 날짜 선택 시 해당 날짜의 주요 이벤트를 상세 표시
- 다가오는 주요 일정을 별도 리스트로 제공

### 4. 속보 및 공시

- DART, SEC EDGAR, KRX/KIND 기반 공시 이벤트 구조 설계
- 공시 유형, 제출 시각, 기업명, 원문 링크를 카드 형태로 표시
- 원문 확인 중심의 UI로 정보 출처를 명확하게 제공

### 5. 수급 및 차트 보드

- 거래대금, 상승률, 거래량, ETF, 위험 필터 기반의 주도주 리스트 구성
- 선택 종목의 관련 뉴스, 공시, 테마 근거를 상세 패널로 표시
- 데스크톱에서는 리스트와 상세 패널을 함께 보여주고, 모바일에서는 세로 카드 흐름으로 재배치

## 아키텍처 설계

외부 API별 인증 방식과 응답 구조가 다르기 때문에 각 공급자를 adapter로 분리했습니다. UI는 개별 API 응답을 직접 사용하지 않고, `MarketBoardData` DTO로 정규화된 데이터만 사용합니다.

```text
External APIs
  -> Adapter Layer
  -> Provider Orchestration
  -> Normalized MarketBoardData DTO
  -> Next.js Page / API Route
  -> MarketBoard Client Component
  -> Tabbed Dashboard UI
```

이 구조를 통해 특정 API가 실패하거나 비활성화되어도 전체 화면이 깨지지 않고, 정상 수신된 데이터만 병합해 렌더링할 수 있게 했습니다.

## 구현에서 신경 쓴 부분

### 데이터 실패에 강한 UI

금융 데이터 API는 키 누락, 인증 실패, 네트워크 지연, 레이트 리밋 가능성이 높습니다. 그래서 provider별 상태를 분리하고, 실패한 공급자의 데이터만 제외한 뒤 나머지 화면은 유지되도록 설계했습니다.

- API adapter 분리
- provider status 표시
- timeout 및 fallback 처리
- 빈 상태에서도 레이아웃 유지

### 고밀도 정보 UI

이 프로젝트는 장식적인 화면보다 실제 사용자가 장중에 반복적으로 확인할 수 있는 UI를 목표로 했습니다.

- 탭 기반 정보 분리
- 카드형 시황 요약
- 표 기반 수급 데이터
- 캘린더 기반 일정 확인
- 원문 링크 중심의 뉴스/공시 리스트

### 반응형 레이아웃

금융 대시보드는 모바일에서 정보가 쉽게 깨질 수 있어 Playwright로 실제 화면을 캡처하고 DOM overflow를 점검했습니다.

- 검증 뷰포트: 1440x900, 768x1024, 390x844, 320x568
- 검증 범위: 시황, 뉴스, 일정, 속보/공시, 수급/차트 전체 탭
- 결과: 전체 문서 기준 가로 스크롤 없음, 주요 탭 렌더링 정상

## AI 활용 방식

AI는 단순 코드 생성 도구가 아니라 기획, 구조화, 검증 속도를 높이는 보조 도구로 활용했습니다.

### 1. 기획 및 정보 구조 정리

금융 시장 사용자가 실제로 확인하는 순서를 기준으로 화면 탭과 정보 우선순위를 정리하는 데 AI를 활용했습니다. 단순히 많은 데이터를 넣는 것이 아니라, 시황 확인에서 뉴스, 일정, 공시, 수급 확인으로 이어지는 흐름을 설계했습니다.

### 2. 리서치 문서화

Yahoo Finance, Bloomberg, TradingView, Finviz 등 금융 서비스의 화면 구조를 분석하고, 정보 밀도, 내비게이션, 신뢰 요소, 데이터 출처 표현 방식을 문서화하는 데 AI를 활용했습니다.

### 3. 코드 구조 설계 보조

여러 외부 API를 adapter 패턴으로 분리하고, UI와 데이터 계층 사이에 DTO 계약을 두는 구조를 설계할 때 AI와 함께 대안을 비교했습니다.

### 4. 반응형 검증 자동화

Playwright 기반 스크린샷 캡처와 DOM overflow scan 스크립트를 만들어 모바일, 태블릿, 데스크톱 화면에서 레이아웃이 깨지는지 확인했습니다.

### 5. 포트폴리오 문서 정리

구현 내용, 기술 스택, 문제 해결 과정, 검증 결과를 면접관이 빠르게 이해할 수 있도록 README와 케이스 스터디 형태로 정리하는 데 AI를 활용했습니다.

## 문제 해결 사례

### 문제 1. API가 실패하면 화면 전체가 비어 보일 수 있음

해결: 공급자별 adapter와 provider status를 분리했습니다. 특정 API가 실패해도 전체 대시보드는 유지하고, 사용 가능한 데이터만 병합해 렌더링하도록 구성했습니다.

### 문제 2. 모바일에서 금융 데이터 테이블이 쉽게 깨짐

해결: 데스크톱에서는 표와 상세 패널을 유지하고, 모바일에서는 카드형 세로 흐름으로 전환했습니다. 긴 기업명, 뉴스 제목, 공시 접수번호는 `overflow-wrap`, `minmax`, 고정 컬럼 전환으로 처리했습니다.

### 문제 3. 많은 정보를 보여주면 사용자가 무엇을 먼저 봐야 하는지 불명확함

해결: 사용자의 확인 순서를 기준으로 탭을 설계했습니다. 시황을 기준점으로 두고, 뉴스, 일정, 공시, 수급으로 이어지는 구조를 만들었습니다.

## 면접 답변용 요약

이 프로젝트는 국내/미국 시장 정보를 한 번에 확인할 수 있는 금융 시장 대시보드입니다. 단순히 데이터를 보여주는 화면이 아니라, 사용자가 장중에 실제로 확인하는 순서에 맞춰 시황, 뉴스, 일정, 공시, 수급 탭으로 정보 구조를 설계했습니다.
