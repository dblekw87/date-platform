# Korean Language Policy

## 기본 원칙

사용자 화면에는 한국어를 기본으로 사용한다. 영어 UX 용어는 원칙적으로 사용하지 않는다. 내부 Architecture 용어는 문서에서 필요한 경우에만 괄호로 병기할 수 있다.

- 현재 보고 있는 정보 Label
- Mock Label

## 권장 표현

| 내부 용어 | 사용자 화면 표현 |
| --- | --- |
| Discovery | 시장 |
| Entity | 종목·기업 정보, 투자 대상 |
| Evidence | 투자 근거 |
| Research | 분석 |
| Monitoring | 변화, 관심 변화, 새롭게 감지된 변화 |
| Journal | 기록, 판단 기록 |
| Workspace | 분석 공간, 이어서 분석 중인 내용 |
| Context | 현재 보고 있는 종목과 근거, 연결 정보 |
| Freshness | 마지막 확인 시점, 다시 확인이 필요한가 |
| Boundary | 이 근거로 확인할 수 있는 내용, 아직 단정할 수 없는 내용 |
| Source | 출처, 어디에서 나온 정보인가 |
| Signal | 새롭게 감지된 변화 |
| Open Question | 아직 확인이 필요한 내용 |

## 문장 작성 기준

- 번역투를 피한다.
- 한 문장에 여러 개념을 넣지 않는다.
- 사용자가 용어를 학습해야 화면을 이해하는 구조를 만들지 않는다.
- 전문 용어가 필요하면 쉬운 설명 뒤에 괄호로 보조한다.

## 금지 예

- 오늘의 디스커버리
- 엔티티를 탐색하세요
- 에비던스를 리뷰하세요
- 리서치 워크스페이스
- 액티브 모니터링
- 컨텍스트를 유지합니다
- 시그널이 트리거되었습니다

## 권장 예

- 오늘 꼭 확인할 시장 변화
- 관련 종목과 기업을 살펴보세요
- 이 판단의 근거를 확인하세요
- 분석 중인 내용
- 현재 감지 중인 변화
- 이어서 보고 있던 내용을 유지했어요
- 새로운 변화가 감지됐어요
