# KR Analysis Experience Planner

## 문서 목적

이 문서는 KR Prototype B의 분석 화면을 구현하기 전 경험 구조를 정의한다.

이번 문서는 코드, route, component, wireframe, mock data, commit을 만들지 않는다. 목적은 사용자가 시장 변화, 종목, 공식 근거, 확인된 사실, 미확인 내용을 자신의 판단 기준으로 구조화하는 경험을 설계하는 것이다.

Prototype A의 Research 화면을 번역하거나 복사하지 않는다. Prototype A는 Architecture 기준이고, Prototype B의 분석 화면은 한국 투자자의 읽는 순서와 판단 준비 흐름을 기준으로 다시 설계한다.

## 1. Analysis Product Goal

### 분석은 왜 존재하는가

분석은 사용자가 공식 정보와 시장 변화를 보고 난 뒤 자신의 판단 과정을 구조화하기 위해 존재한다.

DATE는 투자 결론을 제공하지 않는다. 분석 화면은 매수, 매도, 목표가, 상승 가능성을 제시하지 않는다. 분석 화면의 목표는 사용자가 다음을 구분하도록 돕는 것이다.

- 공식적으로 확인된 사실
- 관찰된 시장 변화
- 사용자의 해석
- 가능한 다른 해석
- 아직 확인되지 않은 내용
- 현재 가설
- 판단을 다시 봐야 하는 조건
- 다음 확인 시점

### 사용자가 해결하는 문제

한국 투자자는 종목 상세와 투자 근거 상세에서 많은 정보를 확인한 뒤에도 다음 문제가 남는다.

- 어떤 내용이 공식 사실인지 헷갈린다.
- 가격 반응과 공식 정보의 관계를 단정하기 쉽다.
- 여러 근거를 비교할 때 어떤 문장이 어떤 근거에 연결되는지 놓친다.
- 아직 모르는 내용을 기록하지 않아 과도한 해석을 하게 된다.
- 시간이 지난 뒤 기존 판단을 왜 세웠는지 되짚기 어렵다.
- 새 공식 정보가 나왔을 때 기존 판단을 어떻게 다시 봐야 하는지 불명확하다.

분석은 이 문제를 “사실, 관찰, 해석, 가설, 미확인 내용, 판단 변경 조건”으로 나누어 관리한다.

### 사용 후 명확해져야 하는 것

분석을 사용한 뒤 사용자는 다음 질문에 답할 수 있어야 한다.

1. 내가 지금 보고 있는 대상은 무엇인가?
2. 현재 질문은 무엇인가?
3. 공식적으로 확인된 사실은 무엇인가?
4. 시장에서 관찰된 변화는 무엇인가?
5. 내가 해석한 내용은 무엇인가?
6. 다른 설명 가능성은 무엇인가?
7. 아직 확인되지 않은 내용은 무엇인가?
8. 어떤 조건이 충족되면 판단을 다시 봐야 하는가?
9. 다음에는 언제, 무엇을 확인해야 하는가?

### DATE 전체 흐름에서의 역할

분석은 Home, 시장, 종목 상세, 투자 근거 상세에서 확인한 정보를 개인 판단 구조로 정리하는 화면이다.

흐름:

```text
Home
→ 시장
→ 종목 상세
→ 투자 근거 상세
→ 분석
→ 변화
→ 기록
```

분석은 현재 판단을 만드는 과정이다. 기록은 특정 시점의 판단을 보존하는 공간이다.

## 2. 다른 화면과의 책임 구분

### 종목 상세

종목 상세는 특정 종목의 현재 변화와 연결 관계를 이해하는 화면이다.

책임:

- 종목명, 코드, 시장, 업종, 테마 확인
- 현재 확인된 변화 확인
- 공식 투자 근거 진입
- 관련 기업, ETF, 시장, 테마 연결
- 시장 반응과 시간순 변화 확인

분석과의 차이:

- 종목 상세는 사용자의 해석을 관리하지 않는다.
- 종목 상세는 판단 변경 조건이나 개인 질문을 소유하지 않는다.
- 종목 상세는 “이 종목에서 무엇이 달라졌는가”를 보여준다.

### 투자 근거 상세

투자 근거 상세는 하나의 공식 정보에서 확인 가능한 사실과 해석 범위를 확인하는 화면이다.

책임:

- 공식 출처와 공개 시각 확인
- 원문에서 확인 가능한 사실 확인
- 이 근거로 확인할 수 없는 내용 확인
- 관련 종목과 시장 반응 연결
- 해석 범위와 제한 확인

분석과의 차이:

- 투자 근거 상세는 하나의 근거를 검증한다.
- 분석은 여러 근거와 사용자의 해석을 연결한다.
- 투자 근거 상세는 사용자의 개인 가설이나 판단 변경 조건을 소유하지 않는다.

### 분석

분석은 여러 근거와 사용자의 해석을 연결해 현재 판단 구조를 관리하는 화면이다.

책임:

- 현재 질문 관리
- 공식 사실과 시장 관찰 분리
- 사용자 해석과 다른 해석 가능성 기록
- 가설과 미확인 내용 관리
- 연결된 투자 근거와 분석 문장 연결
- 판단 변경 조건과 다음 확인 시점 관리
- 변경 이력 관리

### 관심 종목

관심 종목은 관심 대상과 새로운 변화를 추적하는 화면이다.

분석과의 차이:

- 관심 종목은 대상을 유지하고 변화 발생 여부를 알려준다.
- 분석은 해당 변화가 기존 판단에 어떤 영향을 주는지 검토한다.

### 변화

변화는 기존 확인 상태 이후 달라진 내용을 발견하는 화면이다.

분석과의 차이:

- 변화는 새 공식 정보, 정정 정보, 미확인 내용 해소, 시장 급변을 감지한다.
- 분석은 감지된 변화가 사용자의 현재 판단 구조에 어떤 영향을 주는지 관리한다.

### 기록

기록은 특정 시점의 판단과 행동을 보존하고 회고하는 화면이다.

분석과의 차이:

- 분석은 계속 수정 가능한 현재 상태이다.
- 기록은 특정 시점의 판단 구조를 보존하는 과거 상태이다.
- 기록은 결과 회고를 다룰 수 있지만, 수익률 중심 매매일지가 아니다.

## 3. Analysis 진입 경로

### Home의 이어서 분석

유지해야 할 문맥:

- 분석 중인 종목
- 비교 중인 투자 근거
- 아직 확인이 필요한 내용
- 마지막 분석 시점
- 다음 행동

진입 후 첫 노출:

- 이어서 보던 분석 대상
- 새로 달라진 내용 여부
- Primary CTA: 분석 이어서 작성하기

### 시장의 분석으로 이어가기

유지해야 할 문맥:

- 오늘 시장에서 확인한 변화
- 관련 시장
- 관련 테마
- 관련 종목
- 공식 근거 후보
- 확인 상태

진입 후 첫 노출:

- 시장 변화가 어떤 분석 대상과 연결되는지
- 아직 공식 확인이 필요한 항목
- Primary CTA: 새 근거 검토하기

### 종목 상세의 내 분석에 담기

유지해야 할 문맥:

- 종목명
- 종목 코드
- 시장
- 현재 확인된 변화
- 대표 투자 근거
- 관련 테마
- 관련 기업

진입 후 첫 노출:

- 해당 종목을 중심으로 한 분석 초안
- 현재 질문 입력 또는 선택
- 공식 사실과 시장 관찰의 초기 분리

### 투자 근거 상세의 이 근거를 내 분석에 담기

유지해야 할 문맥:

- 투자 근거 식별자
- 공식 출처
- 공개 시각
- 확인된 사실
- 확인할 수 없는 내용
- 관련 종목
- 관련 테마
- 해석 범위

진입 후 첫 노출:

- 이 근거가 어떤 분석 문장에 연결될지 선택
- 새 분석 생성 또는 기존 분석에 추가
- Primary CTA: 근거를 분석에 연결하기

### 관심 종목의 관심 종목 변화

유지해야 할 문맥:

- 관심 종목
- 새롭게 감지된 변화
- 마지막 확인 시점
- 관련 공식 근거
- 기존 분석 존재 여부

진입 후 첫 노출:

- 기존 분석에 새 변화가 연결되는지
- 판단 변경 조건과 맞닿는지

### 변화의 새로 달라진 내용

유지해야 할 문맥:

- 변화 유형
- 관련 종목
- 관련 투자 근거
- 정정 또는 수정 여부
- 기존 미확인 내용 해소 여부
- 판단 변경 조건 충족 여부

진입 후 첫 노출:

- 기존 분석에서 무엇이 달라졌는지
- 다시 검토해야 하는 이유

### `/kr/analysis` 직접 진입

유지해야 할 문맥:

- 최근 분석 목록
- 이어서 볼 분석
- 새 공식 근거가 추가된 분석
- 추가 확인 시점이 도래한 분석

진입 후 첫 노출:

- 이어서 분석할 항목이 있으면 우선 표시
- 없으면 새 분석을 시작할 대상을 선택하게 안내

## 4. Analysis 기본 단위

### 검토 후보

#### 종목 중심

장점:

- 한국 투자자가 가장 익숙한 단위이다.
- 종목 상세에서 자연스럽게 분석으로 이어진다.
- 관심 종목, 변화, 기록과 연결하기 쉽다.

한계:

- 테마나 이벤트가 여러 종목에 걸칠 때 분석이 분산될 수 있다.

#### 기업 중심

장점:

- Security와 Company의 내부 Domain 분리를 유지하기 좋다.
- 기업 발표, 실적, 공급망 분석에 적합하다.

한계:

- 한국 사용자는 화면에서 종목명과 종목 코드를 먼저 기대한다.

#### 테마 중심

장점:

- 반도체, AI 인프라, 배터리처럼 여러 종목을 비교하기 좋다.

한계:

- 초보 사용자에게 분석 대상이 넓어질 수 있다.
- 종목별 판단 변경 조건이 흐려질 수 있다.

#### Event 중심

장점:

- 정책 발표, 공시, 실적 발표처럼 특정 변화 분석에 적합하다.

한계:

- 지속적인 개인 분석 단위로는 익숙하지 않을 수 있다.

#### 투자 근거 중심

장점:

- 공식 정보와 출처 중심으로 분석을 시작하기 좋다.

한계:

- 하나의 근거가 여러 종목과 연결될 때 사용자의 최종 관심 대상이 흐려질 수 있다.

### 권장안

기본 단위는 “종목 중심 분석”으로 둔다.

사용자 화면에서는 종목명과 종목 코드를 중심으로 보여주고, 내부적으로는 Security와 Company 정보를 분리해 유지한다. 테마, Event, 투자 근거는 종목 중심 분석에 연결되는 보조 단위로 둔다.

권장 구조:

```text
분석
├─ 기본 대상: 종목
├─ 연결 기업: Company
├─ 연결 테마
├─ 연결 공식 근거
├─ 연결 시장 변화
└─ 연결 판단 기록
```

### 하나의 종목에 여러 Analysis를 허용할지

권장안: 허용한다.

이유:

- 같은 종목이라도 분석 질문이 다를 수 있다.
- 예: “반도체 규제 영향”, “HBM 수요”, “환율 민감도”는 모두 삼성전자 분석이지만 질문이 다르다.

### 하나의 Analysis에 여러 종목을 연결할지

권장안: 허용하되 대표 종목은 하나만 둔다.

이유:

- 기본 분석 대상은 명확해야 한다.
- 관련 기업과 비교 종목은 보조 연결로 둔다.

### Analysis 제목

권장안: 자동 생성 제목을 기본으로 하고 사용자가 수정할 수 있게 한다.

자동 생성 예:

- 삼성전자: 반도체 공급망 영향 분석
- SK하이닉스: HBM 수요 변화 분석

사용자가 수정할 수 있어야 하는 이유:

- 분석 질문은 개인마다 다를 수 있다.

### 기본 Analysis 생성 조건

권장 조건:

- 종목 상세에서 “내 분석에 담기”를 선택한 경우
- 투자 근거 상세에서 “이 근거를 내 분석에 담기”를 선택한 경우
- 시장 화면에서 특정 변화와 관련 종목을 분석으로 보낸 경우
- 직접 진입 후 종목을 선택한 경우

## 5. Analysis 핵심 구조

1. 분석 대상
   - 무엇을 분석 중인지 가장 먼저 보여준다.
   - 종목명, 종목 코드, 시장, 관련 테마를 포함한다.

2. 현재 질문
   - 사용자가 지금 답하려는 질문이다.
   - 예: “반도체 규제 범위 확대가 삼성전자 공급망에 영향을 줄 수 있는가?”

3. 현재 상태
   - 분석이 작성 중인지, 근거 확인 중인지, 추가 확인이 필요한지 보여준다.

4. 공식적으로 확인된 사실
   - 공식 원문과 발표로 확인된 내용만 표시한다.
   - 출처와 공개 시각을 함께 둔다.

5. 관찰된 시장 변화
   - 가격, 거래량, 지수, 테마, 관련 기업 반응을 분리해 보여준다.
   - 원인으로 단정하지 않는다.

6. 사용자의 해석
   - 사용자가 공식 사실과 관찰을 바탕으로 해석한 내용이다.
   - 시스템 요약과 구분한다.

7. 가능한 다른 해석
   - 현재 해석과 다른 설명 가능성을 기록한다.
   - 과도한 확신을 줄이는 장치이다.

8. 현재 가설
   - 아직 공식 확인되지 않은 임시 판단이다.
   - 사실처럼 보이면 안 된다.

9. 아직 확인되지 않은 내용
   - 현재 정보로 알 수 없는 내용을 명확히 남긴다.

10. 연결된 투자 근거
    - 단순 저장 목록이 아니라 어떤 분석 문장과 연결되는지 보여준다.

11. 관련 종목·기업·테마
    - 비교 대상과 연결 이유를 표시한다.

12. 추가 확인할 항목
    - 어떤 공식 출처나 문서가 더 필요한지 정리한다.

13. 판단이 바뀌는 조건
    - 현재 판단을 다시 검토해야 하는 조건이다.

14. 다음 확인 시점
    - 다시 확인할 날짜나 장 구간을 지정한다.

15. 마지막 업데이트
    - 분석이 언제 갱신됐는지 보여준다.

16. 변경 이력
    - 어떤 항목이 왜 바뀌었는지 남긴다.

## 6. Fact / Observation / Interpretation Boundary

분석의 가장 중요한 원칙은 공식 사실, 관찰, 해석, 가설, 미확인 내용을 같은 문장이나 같은 입력 영역에서 섞지 않는 것이다.

### 공식 사실

정의:

- 공식 원문이나 공식 발표로 확인된 내용

예:

- 공시 공개 시각
- 계약 금액
- 계약 기간
- 실적 수치
- 정책 적용 대상
- 승인 여부

표현:

- 출처와 공개 시각을 함께 표시한다.
- 사용자가 직접 수정하지 못하는 시스템 입력으로 둔다.

### 관찰된 시장 변화

정의:

- 가격, 거래량, 지수, 테마, 관련 기업 반응처럼 관찰 가능한 변화

주의:

- 시장 변화는 원인 설명이 아니다.
- 공식 근거와 동시에 발생했더라도 직접 인과관계를 단정하지 않는다.

### 사용자 해석

정의:

- 공식 사실과 시장 관찰을 사용자가 해석한 내용

표현:

- 사용자가 직접 작성한다.
- “내 해석”이라는 한국어 제목을 사용한다.
- 공식 사실 영역과 시각적으로 분리한다.

### 다른 해석 가능성

정의:

- 현재 해석 외에 가능한 설명

목적:

- 사용자의 과도한 단정을 막는다.
- 같은 시장 반응을 다른 요인으로 볼 수 있음을 남긴다.

### 가설

정의:

- 아직 공식 확인되지 않은 임시 판단

표현:

- “현재 가설”로 표시한다.
- “확정”이나 “결론”처럼 보이면 안 된다.

### 미확인 내용

정의:

- 현재 정보로 확인할 수 없는 내용

예:

- 실적 반영 시점
- 정책 시행일
- 공급 물량
- 관련 기업 공식 입장
- 가격 영향

### 판단 변경 조건

정의:

- 현재 판단을 다시 검토해야 하는 조건

예:

- 후속 공시에서 적용 대상이 제외됨
- 관련 기업이 공식 부인
- 정정 공시 발생
- 다음 확인 시점까지 공식 문서 없음

## 7. Evidence 연결 구조

분석에 투자 근거를 단순 저장하지 않는다. 각 투자 근거가 어떤 분석 문장이나 판단 조건과 연결되는지 보여줘야 한다.

### 각 투자 근거에 포함할 정보

- 투자 근거 제목
- 투자 근거 유형
- 공식 출처
- 공개 시각
- 확인 상태
- 최신 여부
- 정정 또는 수정 여부
- 확인하는 공식 사실
- 확인하지 못하는 내용
- 연결된 분석 문장
- 관련 종목·기업·테마

### 연결 단위 후보

#### 분석 전체

장점:

- 구현이 쉽다.
- 사용자가 빠르게 근거를 모을 수 있다.

한계:

- 어떤 문장을 뒷받침하는지 불명확하다.

#### 특정 Section

장점:

- Low-Fi 단계에서 현실적이다.
- 공식 사실, 내 해석, 미확인 내용, 판단 변경 조건에 각각 근거를 연결할 수 있다.

한계:

- 문장 단위보다 정밀도는 낮다.

#### 특정 문장

장점:

- 가장 정확하다.
- 근거와 해석의 연결이 명확하다.

한계:

- 작성 UX가 복잡해질 수 있다.

#### 특정 가설

장점:

- 가설 검증 흐름에 적합하다.

한계:

- 모든 근거가 가설에만 연결되는 것은 아니다.

#### 특정 판단 변경 조건

장점:

- 새 공식 정보 발생 시 재검토에 유용하다.

한계:

- 초기 사용자에게 설정 부담이 생길 수 있다.

### Low-Fi 권장안

Low-Fi에서는 “Section 단위 연결”을 기본으로 한다.

권장 연결:

- 공식 사실에 연결된 근거
- 내 해석에 참고한 근거
- 미확인 내용과 연결된 근거
- 판단 변경 조건과 연결된 근거

문장 단위 연결은 후속 단계에서 검토한다.

## 8. 사용자 입력과 시스템 입력

### 시스템 자동 입력

시스템이 채우는 정보:

- 종목명
- 종목 코드
- 시장
- 기업명
- 투자 근거 Metadata
- 공식 출처
- 공개 시각
- 확인 상태
- 관련 대상
- 시장 반응
- 마지막 업데이트
- 새 투자 근거 발생 여부
- 정정 또는 수정 여부

원칙:

- 시스템 입력은 공식 정보와 관찰 정보에 한정한다.
- 시스템이 투자 결론을 작성하지 않는다.
- 시스템 요약은 “사용자가 작성한 해석”과 분리한다.

### 사용자 직접 입력

사용자가 작성하는 정보:

- 현재 질문
- 내 해석
- 다른 해석
- 현재 가설
- 추가 확인 항목
- 판단 변경 조건
- 다음 확인 시점
- 개인 메모
- 현재 판단 상태

원칙:

- 사용자 입력은 판단 과정에 해당한다.
- 사용자가 작성한 내용은 공식 사실처럼 보이면 안 된다.
- “내가 작성한 내용” 또는 “사용자 작성” 표시를 검토한다.

### AI에 대한 제한

AI가 자동으로 투자 결론을 작성하지 않는다.

허용 가능한 보조:

- 공식 사실과 미확인 내용을 분리해 보여주는 안내
- 사용자가 입력할 항목을 구조화하는 도움말
- 빠뜨린 확인 항목 제안 Placeholder

금지:

- 매수·매도 판단 생성
- 상승 가능성 제시
- 목표가 제시
- “이 종목은 좋다” 같은 결론 생성

| 종료 | 더 이상 추적하지 않기로 한 상태 | 기록 보존 또는 보관 |

- 확정 수익

## 10. 변경 감지

분석 생성 이후 새로운 정보가 발생하면 사용자의 판단을 자동으로 수정하지 않는다.

변경 감지는 “무엇이 달라졌고 왜 다시 봐야 하는가”를 알려주는 역할만 한다.

### 변경 유형

- 새로운 공식 투자 근거 추가
- 기존 투자 근거 정정
- 기존 미확인 내용 공식 확인
- 기존 공식 사실 변경
- 관련 기업 공식 발표
- 관련 시장 급변
- 판단 변경 조건 충족
- 다음 확인 시점 도래
- 분석 대상 종목의 상태 변경

### 표시 방식

분석 첫 화면 상단에 “새로 달라진 내용” 영역을 둔다.

포함:

- 변경 유형
- 달라진 항목
- 연결된 기존 분석 영역
- 다시 봐야 하는 이유
- 확인 상태
- Primary CTA: 새 근거 검토하기

### 원칙

- 변경이 곧 판단 변경을 의미하지 않는다.
- 시스템은 기존 판단을 자동 수정하지 않는다.
- 사용자가 해석 유지, 수정, 보류 중 하나를 선택한다.

- 다음 확인 시점 설정하기
- 분석 복사하기
- 분석 종료하기

금지 CTA:

- 매수하기
- 매도하기
- 투자 결정하기
- AI 판단 받기
- 상승 가능성 보기
- 수익 가능성 확인하기

## 15. Empty State

### Analysis가 하나도 없는 사용자

표현:

- 아직 이어서 볼 분석이 없습니다.
- 오늘 확인한 공식 근거를 분석에 담아보세요.

다음 행동:

- 시장 보기
- 종목 검색
- 공식 근거 확인

### 종목은 선택했지만 Evidence가 없는 경우

표현:

- 이 종목에 연결된 공식 근거가 아직 없습니다.
- 시장 변화와 공식 출처를 먼저 확인해보세요.

다음 행동:

- 시장으로 이동
- 투자 근거 검색

### Evidence는 있지만 사용자 해석이 없는 경우

표현:

- 공식 근거는 담겼지만 아직 내 해석이 없습니다.
- 이 근거로 무엇을 확인할 수 있는지 먼저 정리해보세요.

다음 행동:

- 내 해석 작성하기
- 미확인 내용 정리하기

### 공식 사실이 없는 경우

표현:

- 공식적으로 확인된 사실이 없어 분석을 확정할 수 없습니다.
- 출처가 있는 정보를 먼저 확인해야 합니다.

### 새로운 변화가 없는 경우

표현:

- 새로 달라진 내용은 없습니다.
- 다음 확인 시점에 다시 확인하세요.

### Analysis가 오래된 경우

표현:

- 마지막 확인 이후 시간이 지났습니다.
- 공식 정보가 바뀌었는지 다시 확인하세요.

### 판단 변경 조건이 없는 경우

표현:

- 아직 판단을 다시 볼 조건이 없습니다.
- 어떤 정보가 나오면 해석을 바꿀지 정해두면 좋습니다.

### 알 수 없는 Analysis 접근

표현:

- 확인할 수 없는 분석입니다.
- 검색 또는 시장 화면에서 다시 시작할 수 있습니다.

### 비로그인 상태

표현:

- 로그인 전에는 예시 분석만 볼 수 있습니다.
- 실제 저장은 로그인 이후 제공됩니다.

주의:

- 비로그인 상태를 기술 오류처럼 표현하지 않는다.
- 로그인 유도는 보조 행동으로만 둔다.

## 16. Analysis와 Journal의 경계

### Analysis

Analysis는 현재 판단을 만드는 과정이다.

특징:

- 계속 수정 가능
- 새로운 공식 근거 반영
- 공식 사실, 해석, 가설, 조건 관리
- 현재 상태 중심
- 다음 확인 시점 관리

### Journal

Journal은 특정 시점의 판단을 보존하는 공간이다.

특징:

- 당시 알고 있던 정보 기록
- 당시 판단과 행동 기록
- 이후 달라진 내용 회고
- 과거 시점 중심
- 수익률 중심 매매일지가 아님

### Analysis에서 Journal로 넘기는 시점

권장 시점:

- 사용자가 판단을 확정한 시점
- 실제 행동을 기록할 때
- 분석을 종료할 때
- 중요한 판단 변경이 발생했을 때
- 일정 기간 이후 회고가 필요한 시점

넘길 때 포함할 정보:

- 당시 분석 대상
- 현재 질문
- 공식 사실
- 연결된 투자 근거
- 내 해석
- 미확인 내용
- 판단 변경 조건
- 기록 시점

## 17. Watchlist와 Changes 연결

### Watchlist

Watchlist는 관심 대상을 유지한다.

연결 방식:

- 관심 종목에 분석 존재 여부 표시
- 새 공식 정보 발생 시 관련 분석 표시
- 관심 대상에서 분석으로 이동

책임 제한:

- Watchlist는 분석 내용을 편집하지 않는다.
- Watchlist는 판단 변경 조건을 소유하지 않는다.

### Changes

Changes는 기존 분석 이후 달라진 내용을 발견한다.

연결 방식:

- 새 투자 근거
- 정정 정보
- 미확인 내용 해소
- 판단 변경 조건 접근
- 재검토 필요 상태

책임 제한:

- Changes는 변화를 발견한다.
- Analysis는 변화가 현재 판단에 미치는 의미를 검토한다.
- Changes가 사용자의 판단을 자동 수정하지 않는다.

## 18. DATE만의 차별점

### 증권사 종목 메모와의 차이

증권사 메모는 보통 자유 메모에 가깝다. DATE 분석은 공식 사실, 관찰, 해석, 미확인 내용, 판단 변경 조건을 분리한다.

### 일반 메모장과의 차이

일반 메모장은 투자 근거와 문장 연결이 약하다. DATE 분석은 어떤 근거가 어떤 분석 영역을 뒷받침하는지 보여준다.

### Notion 투자 기록과의 차이

Notion은 유연하지만 사용자가 구조를 직접 만들어야 한다. DATE 분석은 처음부터 투자 판단 준비에 맞는 구조를 제공한다.

### AI 종목 분석과의 차이

AI 종목 분석은 결론처럼 보일 위험이 있다. DATE 분석은 사용자의 판단 과정을 구조화할 뿐 투자 결론을 대신 내리지 않는다.

### 뉴스 북마크와의 차이

뉴스 북마크는 저장 중심이다. DATE 분석은 공식 출처, 공개 시각, 확인된 사실, 미확인 내용을 분리한다.

### 매매일지와의 차이

매매일지는 결과와 행동 기록에 가까울 수 있다. DATE 분석은 판단을 만들기 전의 검토 과정이다.

### DATE Analysis 차별점

- 공식 사실과 사용자 해석 분리
- 투자 근거와 분석 문장 연결
- 미확인 내용 관리
- 다른 해석 가능성 기록
- 판단 변경 조건 관리
- 새 공식 정보 발생 시 재검토
- 당시 판단 구조 변경 이력
- 투자 추천 없이 판단 과정 지원

## 19. North Star

분석의 성공은 사용자가 많은 글을 작성한 것이 아니다.

성공한 분석은 사용자가 다음을 명확하게 구분하게 한다.

- 내가 알고 있는 것
- 공식적으로 확인된 것
- 내가 해석한 것
- 아직 모르는 것
- 판단을 바꿔야 하는 조건
- 다음에 확인할 것

분석 화면은 정보 소비 화면이 아니라 판단 과정을 정리하는 개인 분석 공간이다.

## 20. Open Questions

### 1. Analysis 기본 단위를 종목으로 고정할 것인가?

현재 권장안:

- 기본 단위는 종목 중심으로 둔다.

대안:

- 기업 중심 또는 테마 중심.

보류 이유:

- 한국 사용자는 종목명과 종목 코드를 기준으로 진입하지만, 내부 Domain은 Security와 Company를 분리해야 한다.

### 2. 하나의 종목에 여러 Analysis를 허용할 것인가?

현재 권장안:

- 허용한다.

대안:

- 종목당 하나의 분석만 허용한다.

보류 이유:

- 질문별 분석이 많아질 때 목록과 상태 관리가 복잡해질 수 있다.

### 3. 여러 종목을 하나의 Analysis에 연결할 수 있는가?

현재 권장안:

- 대표 종목 1개와 관련 종목 여러 개를 허용한다.

대안:

- 처음부터 여러 종목 비교 분석을 허용한다.

보류 이유:

- 첫 버전에서 비교 분석이 너무 강해지면 기본 분석 대상이 흐려질 수 있다.

### 4. Analysis 제목은 자동 생성인가, 사용자 입력인가?

현재 권장안:

- 자동 생성 후 사용자 수정 허용.

대안:

- 전부 사용자 입력.

보류 이유:

- 자동 제목 품질과 한국어 자연스러움을 검증해야 한다.

### 5. Evidence 연결은 문장 단위인가, Section 단위인가?

현재 권장안:

- Low-Fi에서는 Section 단위 연결.

대안:

- 문장 단위 연결.

보류 이유:

- 문장 단위 연결은 정확하지만 작성 UX가 복잡해질 수 있다.

### 6. 사용자 해석과 시스템 요약을 어떻게 시각적으로 구분할 것인가?

현재 권장안:

- “공식 사실”, “관찰된 변화”, “내 해석” 제목과 입력 상태를 분리한다.

대안:

- 색상이나 아이콘으로 강하게 구분한다.

보류 이유:

- Low-Fi 단계에서는 브랜드 컬러와 아이콘을 확정하지 않는다.

### 7. 판단 변경 조건은 자유 입력인가, 구조화 입력인가?

현재 권장안:

- 자유 입력 + 조건 유형 선택을 함께 검토한다.

대안:

- 완전 자유 입력 또는 완전 구조화 입력.

보류 이유:

- 초보자에게 구조화 입력이 유용하지만, 너무 제한적이면 실제 판단 조건을 담기 어렵다.

### 8. 다음 확인 시점은 날짜만 제공할 것인가, 알림까지 포함할 것인가?

현재 권장안:

- Low-Fi에서는 날짜와 장 구간만 제공한다.

대안:

- 실제 알림까지 연결한다.

보류 이유:

- 알림은 Changes 또는 Watchlist 책임과 겹칠 수 있다.

### 9. 자동 저장은 언제 도입할 것인가?

현재 권장안:

- Low-Fi에서는 저장 기능을 구현하지 않고 Placeholder로 둔다.

대안:

- 작성 즉시 자동 저장.

보류 이유:

- Authentication과 backend가 아직 범위 밖이다.

### 10. 변경 이력은 전체 문서 Snapshot인가, 변경 항목 중심인가?

현재 권장안:

- 변경 항목 중심으로 시작한다.

대안:

- 전체 Snapshot 보존.

보류 이유:

- Journal과 책임이 겹치지 않게 해야 한다.

### 11. Analysis 상태를 사용자가 직접 바꾸는가, 시스템이 제안하는가?

현재 권장안:

- 시스템이 상태 후보를 제안하고 사용자가 확정한다.

대안:

- 사용자가 직접 변경하거나 시스템이 자동 변경.

보류 이유:

- 자동 변경은 투자 판단을 대신하는 것처럼 보일 수 있다.

### 12. 비로그인 사용자는 어디까지 사용할 수 있는가?

현재 권장안:

- 예시 분석과 읽기 흐름은 허용하고 실제 저장은 제한한다.

대안:

- 분석 화면 전체 차단 또는 임시 저장 허용.

보류 이유:

- Guest 경험과 저장 기능 범위가 아직 확정되지 않았다.

### 13. Analysis에서 Journal로 넘기는 정확한 조건은 무엇인가?

현재 권장안:

- 사용자가 판단을 확정하거나 분석을 종료할 때 넘긴다.

대안:

- 일정 기간마다 자동 기록 후보를 만든다.

보류 이유:

- 자동 기록은 사용자의 판단 책임과 충돌할 수 있다.

### 14. Watchlist와 Analysis의 중복 책임을 어떻게 방지할 것인가?

현재 권장안:

- Watchlist는 관심 대상과 변화 발생 여부만 담당하고, Analysis는 판단 구조를 담당한다.

대안:

- Watchlist 안에서 간단한 분석 상태를 편집하게 한다.

보류 이유:

- 관심 종목 화면이 분석 화면처럼 복잡해질 위험이 있다.

### 15. 새 Evidence 발생 시 Analysis 첫 화면을 어떻게 변경할 것인가?

현재 권장안:

- 첫 화면 상단에 “새로 달라진 내용”을 표시하고, 기존 판단을 자동 수정하지 않는다.

대안:

- 새 근거를 자동으로 공식 사실 또는 해석에 반영한다.

보류 이유:

- 자동 반영은 사용자가 모르는 사이 판단 구조가 바뀌는 경험을 만들 수 있다.

- 공식 사실과 사용자 해석이 분리되는가?
- 투자 추천, 매수·매도 유도, 수익 보장 표현이 없는가?
- 시스템 입력과 사용자 입력이 구분되는가?
- 분석과 기록의 책임이 분리되는가?
- 관심 종목과 변화의 책임을 침범하지 않는가?
- 한국어 문장이 번역투처럼 보이지 않는가?
- 영어 UX 용어가 사용자 화면 문구로 남지 않는가?
- 모바일에서 첫 화면에 현재 질문과 다음 행동이 보이는가?

## 구현 동기화 노트

KR Analysis Low-Fi 구현과 Major Audit 이후 다음 기준을 현재 구현 결과로 확정한다.

### 상태별 상단 우선순위

상태별로 같은 화면 구조를 복제하지 않고, 상태에 따라 Section 노출 순서를 다르게 둔다.

- 새 근거 검토 필요: 새로 달라진 내용 → 연결된 공식 근거 → 현재 질문 → 공식 사실 → 관찰된 시장 변화 → 내 해석 → 미확인 내용 → 판단 변경 조건
- 추가 확인 필요: 미확인 내용 → 다음 확인 항목 → 현재 질문 → 공식 사실 → 내 해석 → 판단 변경 조건 → 연결된 공식 근거 → 관찰된 시장 변화
- 작성 중: 현재 질문 → 내 해석 → 현재 가설 → 공식 사실 → 미확인 내용 → 연결된 공식 근거 → 관찰된 시장 변화

상단 우선순위는 투자 결론을 제안하기 위한 것이 아니라, 사용자가 먼저 검토해야 할 정보의 성격을 분리하기 위한 장치이다.

### Unknown Analysis

알 수 없는 Analysis 접근은 오류 화면으로 처리하지 않는다. Hero 다음에 즉시 Empty State를 노출하고, 일반 Analysis 섹션은 렌더링하지 않는다.

Primary CTA는 “종목에서 분석 시작하기”로 둔다. 보조 행동은 “공식 근거에서 시작”, “시장으로 돌아가기”로 제한한다.

### 모바일 접기 대상

Mobile에서는 긴 스크롤 부담을 줄이기 위해 다음 섹션을 기본 요약 후 펼치기 구조로 둔다.

- 다른 해석 가능성
- 현재 가설
- 관련 대상
- 변경 이력

다음 섹션은 분석 진행에 필요한 핵심 정보이므로 기본 노출한다.

- 미확인 내용
- 판단 변경 조건
- 다음 확인 항목

Desktop에서는 모바일용 접기 UI를 노출하지 않고 전체 내용을 펼쳐 보여준다.

### Evidence 연결 표현

연결된 투자 근거는 북마크 목록이 아니라 어떤 Analysis 영역과 연결되는지 함께 표시한다.

Low-Fi 구현 기준 연결 단위는 Section 단위이다.

- 공식 사실
- 내 해석
- 다른 해석
- 미확인 내용
- 판단 변경 조건

문장 단위 연결은 향후 Interaction 설계에서 확장 후보로 남긴다.

### Analysis 상태 표현

현재 구현은 다음 상태를 중심으로 검증한다.

- 새 근거 검토 필요
- 추가 확인 필요
- 작성 중

상태는 수익, 손실, 매수, 매도 같은 투자 성과나 매매 행동으로 표현하지 않는다.

### Major Audit 결과

Major Audit 기준 결과는 Ready for Commit으로 판단한다.

- 상태별 상단 우선순위: 해결
- unknown Empty-first: 해결
- 모바일 접기: 해결
- 섹션 표현 차별화: 주요 문제는 해결, 세부 시각 리듬은 후속 개선 후보
