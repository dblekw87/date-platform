# KR Changes Experience Planner

## 문서 목적

이 문서는 KR Prototype B의 변화 화면을 구현하기 전 경험 구조를 정의한다.

이번 문서는 코드, route, component, wireframe, mock data, commit을 만들지 않는다. 목적은 사용자가 이전에 확인하거나 분석했던 내용 이후 무엇이 새로 달라졌는지, 왜 다시 확인해야 하는지, 어떤 분석을 재검토해야 하는지 이해하는 경험을 설계하는 것이다.

Prototype A의 Monitoring 화면을 번역하거나 복사하지 않는다. Prototype B의 변화 화면은 한국 투자자가 이미 알고 있던 상태와 새롭게 확인된 상태의 차이를 이해하고, 기존 분석을 다시 볼지 판단하는 흐름을 기준으로 설계한다.

## 1. Changes Product Goal

### 변화는 왜 존재하는가

변화는 사용자가 마지막으로 확인한 상태 이후 달라진 내용을 비교하기 위해 존재한다.

DATE에서 변화 화면은 뉴스 피드, 알림 목록, 급등락 감지 화면이 아니다. 변화는 사용자가 이미 알고 있던 공식 사실, 미확인 내용, 분석 질문, 판단 변경 조건과 새롭게 확인된 내용을 비교해 “다시 봐야 하는 이유”를 알려주는 화면이다.

### 사용자는 무엇을 확인하는가

사용자는 변화 화면에서 다음을 확인한다.

- 마지막 확인 이후 새롭게 확인된 공식 정보
- 기존 공식 정보의 정정, 삭제, 철회
- 기존 미확인 내용이 공식적으로 확인되었는지 여부
- 기존 분석에 직접 영향을 줄 수 있는 변화
- 판단 변경 조건에 가까워진 항목
- 관심 종목 또는 관련 테마에서 새로 달라진 내용
- 아직 공식 근거가 없는 시장 관찰
- 이미 확인했지만 분석에 반영하지 않은 변화

### 사용 후 해야 하는 일

변화 화면을 본 뒤 사용자는 다음 중 하나를 선택할 수 있어야 한다.

- 새 공식 근거를 확인한다.
- 연결된 분석을 다시 검토한다.
- 달라진 내용을 분석에 반영한다.
- 아직 미확인인 항목을 유지한다.
- 중요하지 않은 변화는 보류하거나 무관함으로 표시한다.
- 모든 변화가 반영된 경우 다음 확인 시점을 설정한다.

변화 화면은 사용자의 판단을 자동으로 바꾸지 않는다. 시스템은 다시 봐야 하는 이유를 제안하고, 판단과 반영 여부는 사용자가 결정한다.

## 2. 다른 화면과의 책임 구분

### 홈

홈은 오늘 시장에서 먼저 볼 변화를 안내한다.

변화와의 차이:

- 홈은 첫 진입 이해를 담당한다.
- 변화는 사용자가 이전에 본 상태 이후 달라진 내용을 비교한다.
- 홈은 “오늘 무엇을 먼저 볼 것인가”를 묻고, 변화는 “내가 알고 있던 것과 무엇이 달라졌는가”를 묻는다.

### 시장

시장은 시장 전체 변화와 테마, 종목, 공식 근거의 흐름을 탐색한다.

변화와의 차이:

- 시장은 전체 시장을 보는 탐색 화면이다.
- 변화는 사용자와 연결된 관심 종목, 분석, 근거 기준으로 달라진 내용을 보여준다.
- 시장은 넓게 보고, 변화는 내 기준으로 다시 볼 항목을 좁힌다.

### 종목 상세

종목 상세는 특정 종목의 현재 상태와 연결 관계를 이해하는 화면이다.

변화와의 차이:

- 종목 상세는 현재 상태를 보여준다.
- 변화는 이전 확인 상태와 현재 상태의 차이를 보여준다.
- 종목 상세는 종목 중심, 변화는 재검토 필요성 중심이다.

### 투자 근거 상세

투자 근거 상세는 하나의 공식 정보에서 확인 가능한 사실과 해석 범위를 검증하는 화면이다.

변화와의 차이:

- 투자 근거 상세는 원문, 사실, 해석 범위, 미확인 내용을 분리한다.
- 변화는 새 근거 또는 정정 근거가 기존 분석과 무엇을 다르게 만드는지 보여준다.

### 분석

분석은 사용자의 현재 판단 구조를 관리하는 화면이다.

변화와의 차이:

- 변화는 새로 달라진 내용을 발견하고 재검토 이유를 제시한다.
- 분석은 그 변화를 공식 사실, 시장 관찰, 사용자 해석, 가설, 미확인 내용, 판단 변경 조건에 반영할지 관리한다.
- 변화가 판단을 자동 수정하지 않는다.

### 관심 종목

관심 종목은 사용자가 계속 추적할 대상을 유지한다.

변화와의 차이:

- 관심 종목은 대상 목록과 새 변화 존재 여부를 담당한다.
- 변화는 해당 변화가 왜 중요한지, 기존 분석과 연결되는지, 어떤 근거가 있는지를 비교한다.

### 기록

기록은 특정 시점의 판단과 행동을 보존한다.

변화와의 차이:

- 기록은 과거 시점의 판단 구조를 보존한다.
- 변화는 현재 새로 달라진 내용을 보여준다.
- 변화에서 분석을 재검토한 뒤, 사용자가 판단을 보존할 때 기록으로 이어진다.

## 3. Change의 기본 단위

### 변화 단위 후보

#### Evidence 변화

공식 근거가 새로 추가되거나, 정정되거나, 철회되는 변화이다.

우선순위:

- 공식성 때문에 가장 높은 우선순위를 가질 수 있다.
- 기존 분석과 연결될 때 더 중요하다.

연결 관계:

- 투자 근거 상세
- 연결된 분석
- 관련 종목
- 관련 테마

#### 종목 변화

관심 종목 또는 관련 종목에서 새 공식 정보, 시장 반응, 테마 연결 변화가 발생한 경우이다.

우선순위:

- 관심 종목이거나 분석 대상이면 높다.
- 가격 변화만 있으면 낮다.

연결 관계:

- 종목 상세
- 분석
- 투자 근거

#### Analysis 변화

기존 분석의 미확인 내용, 판단 변경 조건, 다음 확인 시점과 직접 연결되는 변화이다.

우선순위:

- 사용자의 현재 판단 구조에 직접 영향을 주므로 높다.

연결 관계:

- 분석
- 연결된 투자 근거
- 변경 이력

#### Theme 변화

관련 테마가 새 공식 정보, 관련 종목 확산, 시장 반응으로 확대 또는 약화되는 변화이다.

우선순위:

- 분석 대상 또는 관심 종목과 연결될 때 높다.
- 단순 인기 테마 변화는 낮다.

연결 관계:

- 시장
- 관련 종목
- 관련 분석

#### Event 변화

정책 발표, 실적 발표, 계약 공시, 규제 변경처럼 특정 사건의 상태가 달라지는 변화이다.

우선순위:

- 공식 정보가 있고 기존 미확인 내용과 연결되면 높다.

연결 관계:

- 투자 근거
- 시장 흐름
- 관련 종목

#### 시장 기준점 변화

환율, 금리, 유가, 금값, 주요 지수, 선물 등 시장 기준점이 크게 달라진 경우이다.

우선순위:

- 단순 등락이 아니라 기존 분석 조건 또는 관심 종목 영향과 연결될 때 높다.

연결 관계:

- 시장
- 관련 테마
- 분석의 판단 변경 조건

### 권장 기본 단위

대표 변화 단위는 “공식 정보 또는 기존 분석에 영향을 주는 변경”으로 둔다.

권장 구조:

```text
변화
├─ 공식 정보 변화
├─ 기존 분석 영향
├─ 미확인 내용 상태 변경
├─ 정정 또는 철회
├─ 관심 종목 연결
└─ 시장 기준점 변화
```

단순 가격 변동만으로 Change를 만들지 않는다. 가격 변화는 공식 정보, 기존 분석 조건, 관심 종목 영향과 연결될 때 보조 변화로 표시한다.

표현 원칙:

- 공식적으로 확인된 변화와 시장 관찰만 있는 변화를 구분한다.
- 시장 반응을 변화의 원인으로 단정하지 않는다.
- 정정, 철회, 기존 공식 사실 변경은 우선적으로 노출한다.

## 5. Before / After 구조

Changes의 핵심은 새 정보를 나열하는 것이 아니라 이전 상태와 현재 상태를 비교하는 것이다.

각 Change는 다음 구조를 가진다.

- 이전에 알고 있던 내용
- 새로 확인된 내용
- 무엇이 달라졌는가
- 왜 중요한가
- 기존 분석 영향 여부
- 새 투자 근거
- 아직 남은 미확인 내용
- 다음 행동

### 표현 예시

```text
이전에 알고 있던 내용
정책 적용 범위가 아직 확인되지 않았습니다.

새로 확인된 내용
공식 문서 후보에서 일부 적용 범위가 확인됐습니다.

무엇이 달라졌는가
기존 미확인 항목 중 하나가 공식 근거와 연결됐습니다.

왜 중요한가
삼성전자 공급망 영향 분석의 판단 변경 조건과 연결됩니다.
```

### UX 원칙

- 개발자용 diff 도구처럼 보이면 안 된다.
- 삭제선, 코드 diff, 복잡한 버전 비교는 Low-Fi 기본 구조에서 사용하지 않는다.
- 짧은 한국어 문장과 구분된 블록으로 표현한다.
- 핵심 변화 한 문장을 먼저 보여주고, Before / After는 그 아래에 둔다.

## 6. Relevance

모든 변화는 동일하게 중요하지 않다. 관련도는 다음 기준으로 판단한다.

- 내 관심 종목과 연결되는가
- 내 분석과 연결되는가
- 판단 변경 조건과 연결되는가
- 공식 투자 근거가 있는가
- 정정 또는 철회인가
- 시장 영향 범위가 넓은가
- 관련 종목 수가 많은가
- 마지막 확인 이후 새롭게 확인된 정보인가
- 확인 상태가 공식 확인인가, 미확인인가

금지 기준:

- 단순 조회수
- 단순 급등률
- 인기 검색어
- 추천 알고리즘 점수
- 수익 가능성

관련도는 투자 추천이 아니라 재검토 필요성을 정렬하기 위한 기준이다.

## 7. Priority

Priority는 등락률이 아니라 공식성, 관련성, 기존 판단 영향도를 기준으로 한다.

### Priority 1

가장 먼저 확인해야 하는 변화.

포함:

- 기존 공식 사실 정정
- 기존 투자 근거 삭제 또는 철회
- 판단 변경 조건 충족
- 기존 미확인 내용 공식 확인
- 기존 공식 사실과 충돌하는 새 공식 정보

사용자 문구:

- 먼저 확인해야 하는 변화입니다.
- 기존 분석을 다시 볼 필요가 있습니다.

### Priority 2

기존 분석이나 관심 대상에 직접 연결될 가능성이 큰 변화.

포함:

- 새 공식 투자 근거
- 관련 기업 공식 발표
- 기존 Analysis 직접 영향
- 정정은 아니지만 기존 해석에 영향을 줄 수 있는 공식 정보

사용자 문구:

- 새 공식 정보가 추가됐습니다.
- 연결된 분석에서 확인할 수 있습니다.

### Priority 3

관심 대상 또는 시장 흐름과 연결되는 변화.

포함:

- 관심 종목 변화
- 관련 테마 변화
- 시장 기준점 변화
- 관련 종목 반응

사용자 문구:

- 관심 대상과 연결된 변화입니다.
- 아직 공식 인과관계는 확인되지 않았습니다.

### Priority 4

참고 가능한 보조 변화.

포함:

- 공식 근거가 없는 시장 관찰
- 분석과 직접 연결되지 않은 테마 변화
- 확인 상태가 낮은 정보

사용자 문구:

- 참고용으로 확인할 수 있는 변화입니다.

## 8. Change 상태

변화 상태는 매매 행동이나 수익 결과가 아니라 검토 진행 상태를 나타낸다.

| 상태 | 의미 | 다음 행동 |
| --- | --- | --- |
| 새로 확인됨 | 마지막 확인 이후 새 정보가 추가됨 | 공식 근거 확인 |
| 검토 필요 | 기존 분석 또는 조건과 연결됨 | 분석 다시 확인 |
| Analysis 영향 있음 | 특정 분석 Section에 영향을 줄 수 있음 | 연결된 분석 이동 |
| 미확인 유지 | 새 정보가 있지만 아직 공식 확인이 부족함 | 필요한 출처 확인 |
| 공식 확인 완료 | 공식 출처와 공개 시각이 확인됨 | 근거 상세 확인 |
| 정정됨 | 이전 공식 정보가 수정됨 | 기존 분석 재검토 |
| 반영 완료 | 사용자가 분석에 반영했다고 표시함 | 변경 이력 확인 |
| 보류 | 사용자가 나중에 보기로 둠 | 보류 목록 유지 |
| 더 이상 추적하지 않음 | 사용자가 무관하다고 판단함 | 숨김 또는 보관 |

금지 상태:

- 매수
- 매도
- 수익
- 손실
- 성공
- 실패
- 급등 기회
- 추천

## 9. Analysis 연결

Changes는 기존 Analysis와 다음 방식으로 연결된다.

각 Change에 포함할 정보:

- 연결된 분석 제목
- 분석 대상 종목
- 영향받는 Section
- 새로 추가된 투자 근거
- 기존 판단 변경 조건
- 재검토 필요 이유
- 마지막 검토 시각
- 현재 분석 상태

### 영향받는 Section 후보

- 공식적으로 확인된 사실
- 내 해석
- 다른 해석 가능성
- 현재 가설
- 아직 확인되지 않은 내용
- 판단 변경 조건
- 다음 확인 항목

### UX 원칙

- Changes는 사용자의 분석 내용을 자동으로 수정하지 않는다.
- “이 변화가 어떤 분석 영역과 연결되는지”만 보여준다.
- 사용자가 분석으로 들어가 반영 여부를 결정한다.

Primary CTA 후보:

- 분석 다시 확인하기
- 새 근거 검토하기
- 달라진 내용 반영하기

## 10. Evidence 연결

각 Change에는 가능한 경우 투자 근거를 연결한다.

포함 정보:

- 투자 근거 제목
- 공식 출처
- 공개 시각
- 확인 상태
- 정정 여부
- 이전 투자 근거와의 관계
- 확인 가능한 사실
- 확인할 수 없는 내용

### Evidence가 있는 변화

표현:

- 공식 출처와 공개 시각을 제목 가까이에 둔다.
- 정정 정보이면 “정정됨”을 우선 표시한다.
- 이전 근거와 무엇이 달라졌는지 보여준다.

### Evidence가 없는 변화

표현:

- 공식 근거 없음
- 시장 관찰만 확인됨
- 아직 공식적으로 확인된 원인은 없습니다.

원칙:

- Evidence 없는 변화는 공식 사실처럼 보이면 안 된다.
- 가격 반응이나 테마 확산만으로 원인을 단정하지 않는다.

## 11. 시간 구조

Changes는 최신순 목록만으로 만들지 않는다. 사용자의 기준 시점이 명확해야 한다.

### 기준 시점 후보

- 오늘
- 어제 이후
- 마지막 확인 이후
- 마지막 Analysis 수정 이후
- 최근 7일
- 직접 지정 기간

### 권장 기본값

기본값은 “마지막 확인 이후”로 둔다.

분석과 연결된 변화 묶음에서는 “마지막 Analysis 수정 이후”를 함께 표시한다.

예:

```text
마지막 확인 이후 6개 변화
삼성전자 공급망 영향 분석을 마지막으로 수정한 뒤 2개 변화
```

### 이유

- 사용자는 전체 뉴스 흐름보다 자신이 놓친 변화를 알고 싶어 한다.
- 마지막 접속과 마지막 분석 수정은 목적이 다르므로 둘을 구분한다.

## 12. Grouping

한 화면에 모든 Grouping을 동시에 노출하지 않는다.

### 후보

- 중요도
- 종목
- Analysis
- Evidence 유형
- 날짜
- 상태
- 시장
- 테마

### 권장안

기본 Grouping은 중요도와 Analysis 영향을 중심으로 둔다.

권장 순서:

1. 가장 먼저 확인할 변화
2. Analysis 영향 있음
3. 새 공식 정보
4. 정정 또는 상태 변경
5. 관심 종목 변화
6. 아직 미확인인 내용
7. 반영 완료한 변화

### 대안

종목별 Grouping:

- 관심 종목을 많이 가진 사용자에게 유용하다.
- 단점은 공식 정보의 중요도가 묻힐 수 있다.

날짜별 Grouping:

- 시간 흐름을 이해하기 쉽다.
- 단점은 재검토 우선순위를 약하게 만든다.

Evidence 유형별 Grouping:

- 공시, 기업 발표, 정책 발표를 분리하기 좋다.
- 단점은 사용자의 분석 영향도가 보이지 않을 수 있다.

Desktop은 비교와 재검토에 적합해야 한다.

권장 구조:

   - 새 변화 수
   - Analysis 영향 여부
   - Primary CTA

   - Priority 1 중심

3. 마지막 확인 이후 달라진 내용
   - 전체 변화 요약
   - 공식 정보, 미확인, 정정 상태를 분리

4. Analysis 영향 있음

9. 반영 완료한 변화
   - 읽음과 반영을 분리해 보여준다.

10. 다음 행동
    - 분석 다시 확인
    - 새 근거 확인

### Desktop 원칙

- Before / After는 읽기 쉬운 문장 블록으로 둔다.
- 반복 카드보다 row, list, compact block을 우선한다.

## 16. Empty State

### 새로운 변화 없음

문구:

- 마지막 확인 이후 중요한 공식 변화가 없습니다.
- 기존 분석을 다시 확인하거나 관심 종목을 추가할 수 있습니다.

다음 행동:

- 시장 보기
- 분석 이어서 보기
- 관심 종목 확인

### Analysis 없음

문구:

- 연결된 분석이 아직 없습니다.
- 종목이나 공식 근거에서 분석을 시작하면 이후 달라진 내용을 비교할 수 있습니다.

다음 행동:

- 종목에서 분석 시작
- 공식 근거 확인

### 관심 종목 없음

문구:

- 관심 종목이 없으면 내 기준의 변화가 제한적으로 표시됩니다.
- 먼저 보고 싶은 종목을 추가해보세요.

다음 행동:

- 종목 검색
- 시장에서 종목 보기

### 공식 Evidence 없음

문구:

- 공식적으로 확인된 새 정보는 아직 없습니다.
- 시장 관찰은 참고 정보로만 표시됩니다.

### 모든 변화 검토 완료

문구:

- 확인할 변화는 모두 정리됐습니다.
- 반영 완료한 변화는 변경 이력에서 다시 볼 수 있습니다.

### 오래 접속하지 않은 사용자

문구:

- 마지막 확인 이후 시간이 많이 지났습니다.
- 먼저 공식 정보와 정정 항목부터 확인하세요.

### 알 수 없는 Change 접근

문구:

- 확인할 수 없는 변화입니다.
- 시장, 종목, 분석에서 다시 확인할 수 있습니다.

### 비로그인 상태

문구:

- 로그인 전에는 예시 변화만 볼 수 있습니다.
- 내 분석과 관심 종목 기준의 변화는 로그인 후 제공됩니다.

## 17. Read / Reviewed / Applied 경계

변화를 봤다는 것과 분석에 반영했다는 것은 다르다.

| 상태 | 의미 |
| --- | --- |
| 읽지 않음 | 사용자가 아직 변화 내용을 열지 않음 |
| 확인함 | 사용자가 변화 내용을 읽음 |
| 검토 필요 | 분석 또는 판단 변경 조건과 연결되어 재검토 필요 |
| Analysis에 반영함 | 사용자가 해당 변화를 분석에 반영했다고 표시 |
| 보류 | 사용자가 나중에 다시 보기로 둠 |
| 무관함 | 사용자가 현재 분석과 관련 없다고 판단 |

원칙:

- 읽음 상태만으로 변화가 해결된 것으로 처리하지 않는다.
- 반영 완료는 사용자가 직접 표시한다.
- 시스템은 반영 후보를 제안할 수 있지만 자동 반영하지 않는다.

## 18. Notification과의 경계

Changes는 알림함이 아니다.

### Notification

역할:

- 새 변화가 있다는 사실을 짧게 알려준다.
- 사용자를 Changes 또는 관련 화면으로 이동시킨다.

포함:

- 짧은 제목
- 변화 유형
- 시간
- 진입 링크

### Changes

역할:

- 무엇이 달라졌는지 비교한다.
- 기존 분석 영향 여부를 확인한다.
- 투자 근거를 검토한다.
- 반영 여부를 관리한다.

원칙:

- 알림은 진입점이고 Changes는 비교와 재검토 공간이다.
- 알림 목록을 변화 화면에 그대로 복사하지 않는다.

## 19. DATE 차별점

### 증권 앱 알림과의 차이

증권 앱 알림은 주로 가격, 체결, 공시 발생을 알려준다. DATE Changes는 이전에 사용자가 알고 있던 상태와 현재 상태의 차이를 보여준다.

### 뉴스 피드와의 차이

뉴스 피드는 새 기사 소비 중심이다. DATE Changes는 공식 Evidence와 기존 분석 영향 중심이다.

### 공시 알림과의 차이

공시 알림은 공시 발생 여부를 알려준다. DATE Changes는 해당 공시가 기존 미확인 내용, 공식 사실, 판단 변경 조건과 어떻게 연결되는지 보여준다.

### 가격 알림과의 차이

가격 알림은 가격 기준점 도달을 알려준다. DATE Changes는 가격 변화만으로 Change를 만들지 않고, 공식 정보나 분석 조건과 연결될 때 보조 정보로 다룬다.

### Watchlist 변화와의 차이

Watchlist는 관심 대상 유지와 추적이 중심이다. Changes는 그 대상에서 무엇이 달라졌고 왜 다시 봐야 하는지 비교한다.

### 일반 활동 로그와의 차이

활동 로그는 사용자가 무엇을 했는지 기록한다. DATE Changes는 정보 상태가 어떻게 바뀌었는지 보여준다.

### DATE Changes 차별점

- 이전 상태와 현재 상태 비교
- 공식 Evidence 기반
- Analysis 영향 표시
- 판단 변경 조건 연결
- 정정 정보 우선
- 읽음과 반영 구분
- 투자 추천 없이 재검토 지원

## 20. North Star

Changes의 성공은 사용자가 많은 알림을 읽는 것이 아니다.

성공한 변화 화면은 사용자가 다음을 명확하게 이해하게 한다.

- 무엇이 달라졌는가
- 이전에 알고 있던 내용과 무엇이 다른가
- 공식적으로 확인된 정보인가
- 아직 확인되지 않은 내용은 무엇인가
- 기존 분석에 어떤 영향을 줄 수 있는가
- 무엇을 다시 확인해야 하는가
- 분석에 반영할지 보류할지 어떻게 결정할 것인가

## 21. Open Questions

### 1. 기본 기준 시점은 마지막 접속인가, 마지막 Analysis 수정인가?

현재 권장안:

- 기본은 마지막 확인 이후로 둔다. 분석 묶음에서는 마지막 Analysis 수정 이후를 함께 표시한다.

대안:

- 전체 화면 기본값을 마지막 Analysis 수정 이후로 둔다.

보류 이유:

- 직접 분석이 없는 사용자도 변화 화면을 사용할 수 있어야 한다.

### 2. Change 기본 단위는 Evidence인가, Analysis 영향인가?

현재 권장안:

- 공식 정보 또는 기존 Analysis에 영향을 주는 변경을 대표 단위로 둔다.

대안:

- 모든 Change를 Evidence 단위로 고정한다.

보류 이유:

- Evidence가 없는 시장 관찰이나 다음 확인 시점 도래도 재검토가 필요할 수 있다.

### 3. 여러 Change를 하나의 Event로 묶을 것인가?

현재 권장안:

- Low-Fi에서는 묶음 후보만 표시하고 기본은 개별 Change로 둔다.

대안:

- 정책 발표, 환율 변화, 관련 기업 발표를 하나의 Event Flow로 묶는다.

보류 이유:

- 자동 묶음이 인과관계를 단정하는 것처럼 보일 수 있다.

### 4. 가격 변화만 있는 경우 어디까지 노출할 것인가?

현재 권장안:

- 가격 변화만 있으면 낮은 우선순위의 시장 관찰로 표시하고 공식 원인처럼 다루지 않는다.

대안:

- 관심 종목이면 가격 변화만으로도 Change 생성.

보류 이유:

- DATE가 가격 알림 서비스처럼 보일 수 있다.

### 5. 읽음과 검토 완료를 분리할 것인가?

현재 권장안:

- 분리한다.

대안:

- 읽으면 자동으로 확인 완료 처리한다.

보류 이유:

- 읽음은 정보 소비이고, 검토 완료는 분석 반영 여부 판단이다.

### 6. Analysis 반영 여부를 사용자가 직접 표시할 것인가?

현재 권장안:

- 사용자가 직접 표시한다.

대안:

- 분석에 들어가면 자동으로 반영 후보 처리한다.

보류 이유:

- 자동 반영은 사용자의 판단 책임과 충돌할 수 있다.

### 7. 정정 Evidence를 기존 Evidence 위에 덮어쓸 것인가?

현재 권장안:

- 덮어쓰지 않고 정정 관계를 별도로 표시한다.

대안:

- 최신 Evidence만 보여주고 이전 Evidence는 숨긴다.

보류 이유:

- 사용자가 어떤 정보가 바뀌었는지 알아야 한다.

### 8. Changes 보관 기간은 얼마인가?

현재 권장안:

- 기본 화면은 최근 7일과 마지막 확인 이후를 중심으로 두고, 오래된 변화는 보관 영역으로 이동한다.

대안:

- 모든 변화를 무기한 노출한다.

보류 이유:

- 변화 화면이 활동 로그처럼 길어질 수 있다.

### 9. 관심 종목이 없는 사용자에게 무엇을 보여줄 것인가?

현재 권장안:

- 시장 전체의 공식 변화 예시와 분석 시작 CTA를 보여준다.

대안:

- 관심 종목 추가 전에는 변화 화면을 비운다.

보류 이유:

- 첫 사용자도 DATE의 변화 개념을 이해해야 한다.

### 10. 알림과 Changes의 연결 시점은 언제인가?

현재 권장안:

- 알림은 새 변화 발생 시 진입점을 제공하고, 실제 비교와 반영 관리는 Changes에서 한다.

대안:

- 알림 안에서 바로 읽음, 보류, 반영 완료를 처리한다.

보류 이유:

- 알림이 작은 Changes 화면처럼 복잡해질 수 있다.

### 11. Mobile에서 Before / After를 어떻게 줄일 것인가?

현재 권장안:

- 핵심 차이 한 문장을 먼저 보여주고, Before / After는 접을 수 있는 짧은 블록으로 둔다.

대안:

- Before / After를 모바일에서는 숨기고 상세 진입 후 보여준다.

보류 이유:

- 변화 화면의 핵심이 비교이므로 완전히 숨기면 목적이 약해진다.

### 12. 비로그인 상태에서 Changes를 허용할 것인가?

현재 권장안:

- 예시 변화는 허용하고, 내 관심 종목과 내 분석 기준 변화는 로그인 후 제공한다.

대안:

- 비로그인 사용자는 Changes 접근 차단.

보류 이유:

- Prototype B 초기 경험에서 변화의 가치를 보여줘야 한다.

### 13. 변화 중요도를 시스템이 제안할지 사용자가 조정할지

현재 권장안:

- 시스템이 중요도를 제안하고 사용자는 보류, 무관함, 반영 완료로 조정한다.

대안:

- 사용자가 직접 Priority를 변경한다.

보류 이유:

- Priority 직접 변경은 초반 UX를 복잡하게 만들 수 있다.

### 14. 동일 종목의 여러 변화 묶음 기준

현재 권장안:

- 동일 종목이라도 정정, 새 공식 정보, 시장 관찰은 분리하고, 화면에서는 종목별 접기 묶음을 제공한다.

대안:

- 종목별로 모든 변화를 하나의 묶음으로 합친다.

보류 이유:

- 정정 정보가 일반 변화에 묻힐 수 있다.

### 15. 반영 완료한 Change를 어디에 보관할지

현재 권장안:

- 변화 화면 하단의 반영 완료 영역과 Analysis 변경 이력에서 확인할 수 있게 한다.

대안:

- 반영 완료 즉시 변화 화면에서 숨긴다.

보류 이유:

- 사용자가 방금 처리한 변화를 되돌아볼 수 있어야 한다.

## 검증 기준

이 문서와 이후 변화 화면 설계는 다음 기준을 통과해야 한다.

- 기존 KR Experience 문서와 충돌하지 않는가?
- 변화가 Analysis 책임을 침범하지 않는가?
- 변화가 Watchlist 책임을 침범하지 않는가?
- 공식 사실과 시장 관찰을 구분하는가?
- 투자 추천, 매수·매도 유도, 수익 보장 표현이 없는가?
- 영어 UX 용어가 사용자 화면 문구로 남용되지 않는가?
- 읽음과 반영 완료가 분리되는가?
- Before / After 구조가 사용자가 이해할 수 있는 한국어 문장으로 표현되는가?
- 모바일에서 첫 화면에 마지막 확인 시점, 새 변화 수, 가장 중요한 변화, Primary CTA가 보이는가?
